# Release Notes - v0.12.0

**Release Date:** 2026-08-01

## Overview

v0.12.0 completes roadmap Phases 2, 4, and 5 — closing out all MCP write tool gaps, adding HTTP API observability endpoints, and delivering aggregated analytics tools. The release also includes a sync resilience fix and updates `aha-go` to v0.9.0 for the new REST API methods.

## Highlights

- **Phase 2 Write Tools** - Four new MCP tools: `create_release`, `delete_idea`, `list_idea_categories`, and `get_feature_ideas`
- **Phase 4 HTTP API** - OpenAPI 3.0 spec at `/api/openapi.json` and Prometheus metrics at `/metrics`
- **Phase 5 Analytics** - `get_ideas_statistics` and `get_features_statistics` for aggregated cache queries
- **Sync Resilience** - GraphQL feature sync falls back to REST API when project resolution fails

## Installation

```bash
# Install AQL CLI
go install github.com/grokify/aha-studio/cmd/aha-studio@v0.12.0

# Install MCP Server
go install github.com/grokify/aha-studio/cmd/aha-mcp-server@v0.12.0
```

## What's New

### Phase 2: Write Tool Gaps

All remaining MCP write tools from the legacy roadmap are now complete:

| Tool | Description |
|------|-------------|
| `create_release` | Create releases with dates, parking lot status, and theme |
| `delete_idea` | Delete ideas with required `confirm: true` safety parameter |
| `list_idea_categories` | List idea categories for a product |
| `get_feature_ideas` | List ideas linked to or promoted from a feature |

Example usage:

```json
{
  "tool": "create_release",
  "arguments": {
    "product_id": "PROD",
    "name": "Q4 2026 Release",
    "start_date": "2026-10-01",
    "release_date": "2026-12-15",
    "theme": "Performance and scalability improvements"
  }
}
```

### Phase 4: HTTP API Observability

**OpenAPI Specification** (`/api/openapi.json`)

The HTTP server now serves a dynamically generated OpenAPI 3.0.3 specification documenting all endpoints, request/response schemas, and security schemes. This enables client generation and API exploration.

**Prometheus Metrics** (`/metrics`)

New metrics endpoint in Prometheus exposition format:

- HTTP request counts and latency histograms by endpoint
- AQL query counts (cache vs API, parse/exec errors)
- Cache hit/miss rates
- Sync operation metrics (count, duration, errors)
- Graph query metrics
- Server uptime

### Phase 5: Analytics Tools

Two new MCP tools query aggregated statistics from the SQLite cache without fetching individual records:

**`get_ideas_statistics`**

Returns counts by status, vote statistics (total, average, max), top ideas by votes, and recent/updated counts.

```json
{
  "tool": "get_ideas_statistics",
  "arguments": {
    "product": "PROD",
    "top_count": 10
  }
}
```

**`get_features_statistics`**

Returns counts by status and release, features with/without releases, and upcoming releases with feature counts.

```json
{
  "tool": "get_features_statistics",
  "arguments": {
    "product": "PROD",
    "upcoming_releases_count": 5
  }
}
```

### Sync Resilience

The GraphQL-based feature sync now falls back to REST API when project resolution fails. This handles cases where the GraphQL API lacks visibility into certain products that the REST API can access.

## Dependency Updates
